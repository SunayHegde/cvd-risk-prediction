# Cardiovascular Disease (CVD) Risk Prediction

UE24CS352A Machine Learning Mini-Project | Team: [Sunay Hegde , PES1UG24AM903] and [Balla Santosh, PES1UG24AM063] | Problem No.: [14]

Predicts whether a patient has cardiovascular disease from routine clinical measurements. Regularized logistic regression
(Ridge, Lasso, Elastic net) is compared with XGBoost (Extreme Gradient Boosting), evaluated with AUROC (Area Under the ROC Curve),
following the reference paper *Predicting Cardiovascular Risk using Electronic Health Records* (Nguyen, CS229). The paper's hospital
data is private, so two public datasets are used instead.

## Datasets
| Dataset | Patients | Features | Target | Positive rate |
|---|---|---|---|---|
| Kaggle Cardiovascular Disease dataset (primary), `data/cardio_train.csv` | 70,000 (68,610 after cleaning) | 11 (+ BMI) | `cardio` | 49.5% |
| Framingham Heart Study (secondary), `data/framingham.csv` | 4,240 | 15 | `TenYearCHD` | 15.2% |

Kaggle cleaning: age converted from days to years, `id` dropped, 1,390 rows with impossible values removed (e.g. blood pressure of -150 or 16,020), BMI (Body Mass Index) added.

## Results (80/20 stratified split, cross-validated grid search)
| Model | Kaggle test AUROC | Framingham test AUROC |
|---|---|---|
| Logistic regression (Ridge) | 0.794 | 0.712 |
| Logistic regression (Lasso) | 0.795 | 0.715 |
| Logistic regression (Elastic net) | 0.794 | 0.714 |
| XGBoost | **0.804** | 0.693 |

Full outputs (metrics, confusion matrix, subgroup AUROC by gender, ROC plots) are in `results/`.

## Setup
Requires Python 3.11 or newer (scikit-learn 1.8 needs it).
```bash
pip install -r requirements.txt
```

## How to run
**1. Notebook (main code, about 5-10 minutes).** Open `cardio_cvd_prediction.ipynb` in Jupyter or VS Code and choose Run All.
It needs `cardio_train.csv` in the same folder or in `data/`. It cleans the data, trains and tunes all four models, prints the results table,
ROC curves, confusion matrix and gender subgroup AUROC, plots XGBoost feature importance, and saves `xgb_cardio_model.joblib`.

**2. Live demo app.** After the notebook has saved the model:
```bash
streamlit run demo_app.py
```
Enter a patient's details in the browser and click **Predict risk** to get the predicted probability of CVD.
This is a course demo, not medical advice.

**3. Command-line script (optional, both datasets).**
```bash
python train.py --csv data/cardio_train.csv --folds 3 --out results/cardio
python train.py --csv data/framingham.csv --out results/framingham
python train.py --csv synthetic --n 20000 --features 1000 --folds 3   # synthetic sparse EHR-like data
```

## Method summary
Stratified 80/20 split. Grid search with cross-validation (3-fold on Kaggle, 5-fold on Framingham) scoring AUROC. Median imputation and scaling
sit inside the pipeline to avoid leakage. XGBoost uses 300 trees, with tuned depth, learning rate and L1/L2 penalties, and `max_delta_step=1`.
The confusion matrix uses the 3rd-quartile probability threshold, as in the reference paper.

## Limitations
Single train/test split with no confidence intervals; the datasets are small tabular risk-factor data, not the paper's large sparse electronic
health record cohort, so numbers are not directly comparable; the Kaggle data has noisy self-reported fields.
